======================================================================================================
파티션 테이블의 rootpartition에 통계정보가 갱신되지 않는 문제
======================================================================================================
핵심 요약
    파티션 테이블에 신규 리프 파티션(Leaf Partition)을 추가한 후에는 반드시 해당 파티션에 대한 최초 ANALYZE 작업을 수행해야 합니다.

주요 문제점
    통계 정보 미갱신: 추가된 리프 파티션 중 단 하나라도 ANALYZE가 진행되지 않으면, 이후 해당 파티션에 데이터 변경(INSERT/UPDATE 등)이 발생해도 Root Partition에 통계 정보가 반영되지 않습니다.
    optimizer_analyze_root_partition (Default : on)을 통하여 리프 파티션의 데이터 변경사항이 있을 경우 자동으로 rootpartition에 통계 갱신이 이루어 지지만 
    위와 같이 추가된 리프 파티션 중 단 하나라도 ANALYZE가 진행 되지 않은 경우 해당 파라미터 값이 동작하지 않음
    성능 영향: Root Partition 수준의 통계가 갱신되지 않으면 쿼리 옵티마이저가 잘못된 실행 계획을 생성할 위험이 있습니다.

대응 가이드
    파티션 생성 후 데이터 입력 및 사용 이전에 해당 신규 리프 파티션에 대해 ANALYZE를 필수적으로 실행해야 정상적인 통계 갱신 체계가 유지됩니다.

개선이 필요한 점

    자동으로 리프 파티션이 추가되면 자동으로 추가된 리프 파티션에 ANALYZE 작업이 자동으로 실행되었으면 좋겠음

DROP TABLE production_lot;

CREATE TABLE production_lot (
    lot_id BIGINT,
    lot_number VARCHAR(50),
    product_id INT,
    equipment_id INT,
    production_date DATE,
    quantity INT,
    status VARCHAR(20)
)
WITH (
    appendoptimized=true,
    orientation=column,
    compresstype=zstd,
    compresslevel=7
)
DISTRIBUTED BY (lot_id)
PARTITION BY RANGE (production_date)
(
    START ('2026-01-01') END ('2026-12-31') EVERY (INTERVAL '1 month')
);

-- analyze 확인

SELECT
    n.nspname AS schema_name,
    c.relname AS table_name,
    lo.statime AS last_analyze_time
FROM
    pg_class c
JOIN
    pg_namespace n ON c.relnamespace = n.oid
LEFT JOIN
    pg_stat_last_operation lo ON lo.objid = c.oid AND lo.staactionname = 'ANALYZE'
WHERE
    c.relkind = 'r' 
    AND n.nspname NOT IN ('pg_catalog', 'information_schema', 'pg_toast', 'gp_toolkit', 'pg_aoseg')
    AND c.relname like 'production_lot%'
ORDER BY
    lo.statime ASC NULLS FIRST;

-- 최종 결론

1. 리프 파티션을 추가한 경우 반드시 추가한 리프파티션 테이블을 analyze를 해야 합니다.
2. 모든 리프 파티션의 통계 실행내역이 있어야 일부 리프 파티션만 analize 작업만으로도 root partition 에도 통계가 자동으로 갱신됩니다.
